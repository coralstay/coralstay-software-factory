# 4.01 마일스톤과 작업 분해

구현은 채점 기준을 요구하지 않는 walking skeleton(M1)에서 시작해, 실측(M2)과 경계선 측정(M3)으로 판단 근거를 쌓은 뒤 오케스트레이터 전체(M4) · 역할 인식 레일(M5) · 정적 분석과 대시보드(M6)로 넓힌다.

## 마일스톤

| ID | 마일스톤 | 범위 | 완료 조건 | 난이도 |
| --- | --- | --- | --- | --- |
| M1 | Walking skeleton | Implementer 하나만 스폰 → 작업 → 토큰 집계 → 회수. 단발 CLI `orchestrator run <taskId>` | 아래 §M1 완료 조건 | 며칠 |
| M2 | 실측 3종 | 헤드리스 세션 간 메시징 실동 여부 · backlog.md의 의존성/마일스톤/상태 필드 실제 지원 범위 · `claude` 프로세스 peak RSS와 API 분당 한도 | 세 항목 각각 4.02 §실측 항목의 판정 기준으로 결과가 나온다 | 낮음 |
| M3 | 경계선 측정 | M1이 남긴 태스크별 성공/실패 · 재작업 · 회귀 기록으로, 4역할이 값을 하는 태스크의 경계선을 이 백로그의 실제 분포에서 정한다 | 1.02 반증 기준을 4.02 §반증 기준 측정으로 판정할 수 있는 표본이 쌓인다. 경계선 값은 TBD(Q-11) | — |
| M4 | 오케스트레이터 | Board Watcher · Request Queue · Allocation Policy · Agent Spawner · Session Registry, 4역할(Implementer · Reviewer · Verifier · Logger) 스폰 | 4역할 1사이클이 태스크 하나에서 Done까지 끝난다. Reviewer · Verifier·AC 판정은 Q-1이 정해진 뒤에만 완료 판정할 수 있다 | 4역할 전체는 추정 불가(Q-1) |
| M5 | claude-code-agile-hooks 역할 인식 확장 | 기존 훅을 role별로 분기한다 | 역할마다 허용 쓰기 범위(3.03)가 훅으로 강제된다 | 중간 |
| M6 | 정적 분석 · 대시보드 | `JavaParser` 콜 그래프 → Javalin + Vis.js 대시보드 | 대시보드에서 태스크별 정적 분석 결과를 사람이 검증한다 | — |

- M4는 이 설계에서 유일하게 처음부터 만들어야 하는 컴포넌트다. 나머지는 기존 저장소를 이어받는다(§컴포넌트별 출발점).
- 4역할 전체의 기간은 추정하지 않는다. Reviewer · Verifier · AC 채점 기준(Q-1)이 없는 한 "완성"의 정의가 없다.
- 난이도 칸은 RFC 12절의 추정을 그대로 옮긴 것이다. 세션 간 메시징 통합은 M2 실측에서 헤드리스 inbox가 동작하면 낮고, 동작하지 않으면 폴백(파일 메일박스) 구현이 필요해 올라간다.

### M1 완료 조건

M1은 agent-orchestrator 저장소의 마일스톤 `m-0`(M1 Walking skeleton (CLI))에 대응한다.

1. `./gradlew test`가 통과한다.
2. 픽스처 E2E에서 다음이 한 번에 성립한다: git worktree · `task/<id>` 브랜치 생성(= 착수, main에 착수 커밋 없음) → Claude Code 헤드리스 실행 → 종료 후 잔존 프로세스 없음 → AC별 커밋 트레일러 → 카드의 Token Budget에 실제치(`session`, 커밋 귀속분은 `TBD(Q-18)` 뒤) 병기 → `.orchestrator/runs.jsonl`과 일치.
3. 회수는 프로세스 · 자손 종료와 Session Registry 제거로 끝난다. 헤드리스 세션은 종료가 곧 컨텍스트 폐기이므로 `/clear` 단계를 두지 않는다(1.02 P3).

M1 범위 밖: Board Watcher · Request Queue · Allocation Policy, 그래프 길이 · 폭 계측, Reviewer · Verifier · Logger, 임베디드 DB · Javalin · JavaParser, cgroups · tmpfs, Claude Code 외 코딩 에이전트.

M1을 먼저 하는 이유: 아직 없는 채점 기준을 요구하지 않는 유일한 조각이면서, Spawner · Registry · 동시성 세마포어 · 토큰 측정을 한 번에 검증한다.

### M4 첫 작업 단위 — 코어 배정

M4의 할당자(Pure Allocator)는 다음 순서로 만든다.

1. 에이전트별로 배정할 CPU 코어 인덱스를 계산한다.
2. `ProcessBuilder` 인자를 `taskset -c 0-3 claude ...` 형태로 조립해 리눅스 커널 격리 명령을 동적으로 붙인다.
3. 가상 스레드 위에서 `git worktree`로 독립 브랜치와 물리 폴더를 만든다.

## 의존 관계

| 선행 | 후행 | 이유 |
| --- | --- | --- |
| M1 | M3 | 경계선 측정의 자료(태스크별 성공/실패 · 재작업 · 회귀)는 M1이 남긴다 |
| M1 | M4 | M4의 Spawner · Registry · 토큰 측정은 M1에서 검증한 것을 확장한다 |
| M2(헤드리스 메시징) | M4의 역할 간 메시징 배선 | 실동하지 않으면 파일 메일박스 폴백으로 설계가 바뀐다(Q-9) |
| M2(peak RSS · API 한도) | M4의 Allocation Policy | 동시성 상한 `min(그래프 폭, 자원 상한)`의 자원 쪽 값이다 |
| Q-1 | M4의 Reviewer · Verifier·AC 완료 판정 | 채점 기준 없이 판정 역할의 완료를 정의할 수 없다 |
| M4 | M5 | role별 분기는 역할 프로세스가 실제로 뜬 뒤에 검증할 수 있다 |

- M2와 M1은 병렬로 진행할 수 있다. M2의 세 실측은 서로 독립이다.
- M5와 M6은 M4 이후 서로 독립이다.

## 작업 분해

마일스톤 · 태스크의 원본은 각 컴포넌트 저장소의 backlog.md다. 이 장은 대응만 적는다.

| 요구사항 ID | backlog 태스크 | 마일스톤 |
| --- | --- | --- |
| (2.03 · 2.04 참조) | 요구사항 ID가 확정되면 태스크 카드가 자신이 구현하는 요구사항 ID를 적고, 이 표에 행을 추가한다 | — |

- 태스크 카드는 자신이 구현하는 요구사항 ID를 적는다(0 문서 정보 §추적 규칙).
- 요구사항 하나는 하나 이상의 태스크 AC로 내려간다. 수용 기준은 4.02에 있다.

## 컴포넌트별 출발점

| 컴포넌트 | 출발점 | 이어받는 것 | 새로 할 것 |
| --- | --- | --- | --- |
| agent-orchestrator | M1 walking skeleton(Java 25 · Gradle) | BacklogClient · WorktreeManager · AgentSpawner · SessionRegistry · CommitLedger의 단위 구현 | 단위들의 배선(`run` 흐름), M4의 Watcher · Queue · Policy |
| claude-code-agile-hooks | 백로그 워크플로 훅 | 브리핑 → draft → promote, `task view` 필독, In Progress + 브랜치 확인, 테스트 게이트 커밋, Done + final summary 게이트 — 콘텐츠 레이어의 70~80% | "역할 하나" 전제를 4역할 분리에 맞게 확장(M5). 착수 검사(승인 게이트 · 작업 순서)를 브랜치 생성 · 전환에 추가하고 `-s "In Progress"`에도 유지(두 시점 — 오케스트레이터 브랜치는 훅을 거치지 않음), 커밋 메시지 태스크 ID 검사(RAIL-025), `(수동)` AC · DoD 예외 (decision-3) |
| coding-agent-git-commit-tool | 커밋 형식 · 트레일러 훅(포맷 레이어) | 커밋 형식 검사, `Task-Id` · `AI-Tool` · `AI-Model` · `Hooks-Commit` · `Signed-off-by` 트레일러 | 토큰 측정 로직 제거(그 저장소 GF-146). 에이전트 판정을 `CLAUDE_CODE_SESSION_ID` · `CLAUDE_PID`로 바꾸고 '프로그램 커밋'(오케스트레이터가 직접 만든 커밋) 구분 설계(GF-130) |
| 토큰 계량 컴포넌트(이름 미정) | 없음 | — | 이름 · 저장소 · 측정 방식 결정과 세션별 토큰 귀속 확인 (`TBD(Q-18)`, 3.05 ADR-021) |
| backlog.md | 외부 오픈소스 CLI | 계층 · 상태 모델, `--dep` 의존성과 readiness 계산, `--check-ac` · `--check-dod` | 신규 구현 없음 |

보조 도구:

- context-hub(chub) — 외부 API 문서 조회와 세션 간 학습(annotation)으로, 회수와 함께 사라지는 컨텍스트의 빈틈을 보완한다. 그대로 쓴다.
- openworker(fork) — GUI 데스크톱 앱이라 헤드리스 임베딩이 안 된다. 재사용하지 않는다. 그 아래의 멀티 프로바이더 추상화(aisuite)가 필요한지는 Q-8이 정한다.
- langtoolchain — 파이프라인 범위에 넣지 않는다.
