# 3.04 인터페이스 계약

컴포넌트는 함수 호출이 아니라 텍스트 산출물로 맞물린다 — 태스크 카드, 커밋 트레일러, 판정 WAL, 실행 기록, 그리고 프로세스 경계와 정책 경계 두 개의 계약이다.

## §1 태스크 카드

backlog.md 태스크 카드(`backlog/tasks/*.md`)를 쓴다. 이 설계가 카드에 거는 계약은 다음이다.

| 필드 | 쓰는 쪽 | 읽는 쪽 | 계약 |
| --- | --- | --- | --- |
| ID · 제목 | PM 모드(승격 시 backlog.md가 ID 부여) | 전원 | 브랜치명 `task/<ID>`와 트레일러 `Task-Id`의 원천 |
| 상태 | Implementer · 사람 | 오케스트레이터 · 훅 | `To Do` · `In Progress` · `Done`만 (§3). 착수 여부는 상태가 아니라 미병합 `task/<ID>` 브랜치로 판단한다 |
| 마일스톤 · `parentTaskId` | PM 모드 | 오케스트레이터(조상 문서 로딩) | 부착 시 루트까지 거슬러 읽는 경로 (ORC-019) |
| 의존(`dependencies`) | PM 모드 · 사람 | 오케스트레이터 | `--dep`로 선언. 순차 체인의 근거 (ORC-006) |
| 대응 소스 파일 | PM 모드 | 오케스트레이터(결합 판정) | 태스크당 파일 하나 (BL-006). 형식 `TBD(Q-13)` |
| 요구사항 ID | PM 모드 | 사람 · 추적 | 구현하는 `<영역>-nnn` (BL-008) |
| AC | PM 모드 | Implementer · Verifier · 훅 | AC 하나 = 함수 하나 (BL-007). `--check-ac`로 체크. 승격 · 착수 전에 하나 이상 있어야 한다 (RAIL-020). 테스트 표식 `<ID>#<n>`. 텍스트 끝이 `(수동)`인 항목은 표식을 요구하지 않는다(문서 전용 카드 등). 그 AC에 걸린 비즈니스 규칙 표식 `<ID>#B<k>`는 그대로 요구한다 (RAIL-019) |
| DoD | 프로젝트 공통 | Verifier · DoD · 훅 | `--check-dod`로 체크. 승격 · 착수 전에 하나 이상 있어야 한다 (RAIL-020). 테스트 표식 `<ID>#D<n>`. 텍스트 끝이 `(수동)`인 항목은 표식을 요구하지 않는다 (RAIL-022) |
| 구현 계획 | PM 모드(승격 전 `draft edit --plan`) | 사람(리뷰) · Implementer · 훅 | SOAP 예약 제목 `### Subjective` · `### Objective` · `### Assessment` · `### Plan`이 이 순서로 한 번씩, 각 본문이 비어 있지 않음 (BL-015, 2.02 구현 계획 형식) |
| 계획 승인 기록 | 사람 | 훅(승인 게이트) | 사람이 자기 키로 서명한 빈 커밋 `Plan-Approved: <ID>`. 카드 필드가 아니라 git 커밋이다. 승인 게이트는 유효한 서명(`%G?` = `G`)에 더해 서명자(`%GS`)가 `humanSigners`(§7)에 있을 때만 통과한다. 서명 키는 둘로 나눈다 — Claude Code 세션은 AI 전용 키로 서명하고, 사람 키는 ssh-agent 밖에 두어 서명할 때마다 암호를 입력한다. 승인 게이트는 착수 검사 두 시점 — `task/<ID>` 브랜치 생성 · 전환과 `-s "In Progress"` — 에 돈다 (BL-017 · RAIL-020, 3.05 ADR-022, decision-2 · decision-3) |
| 결정 · 문서 참조 | PM 모드 | 부착된 에이전트 | `--add-ref decision-N` · `--doc` (BL-010) |
| final summary | Implementer | 사람 · push 게이트 | Done 전환 조건 (BL-009 · RAIL-008) |
| 완료 기록 | 오케스트레이터(`CommitLedger`) | 사람 · Logger | Done 시점에 커밋을 읽어 함수별 작업 내역과 토큰 집계를 기록 (ORC-021). 토큰은 당분간 `session`(실행마다 `ClaudeCodeRunner`가 읽은 `claude -p` JSON `usage`의 입력(캐시 포함) + 출력)만 쓰고, 커밋 귀속분 `commits`는 토큰 계량 컴포넌트(이름 미정)가 정해진 뒤 더한다(`TBD(Q-18)`). 형식 `TBD(Q-20)`. 기록 커밋은 에이전트 판정 환경변수를 지우고 만든다(§2 트레일러) |
| 대시보드 링크 | 오케스트레이터 | 사람 | `http://localhost:8080/dashboard?task=<id>` |

## §2 커밋 메시지 · 트레일러

coding-agent-git-commit-tool이 검사하고 붙인다 (TRL-001 ~ TRL-003 · TRL-006 · TRL-008). 커밋 하나 = AC 하나 = 함수 하나다. 이 도구는 포맷만 맞추고 토큰을 재지 않는다 — 토큰은 토큰 계량 컴포넌트(이름 미정)의 몫이다 (3.05 ADR-021).

```text
[<type>][<subsystem>] <설명>            ← 사람 또는 에이전트가 씀
                                        ← 빈 줄
<본문: 왜 바꿨는지>                      ← 선택
                                        ← 빈 줄
Task-Id: <PREFIX>-<번호>                ↓ 이하 훅이 자동으로 붙임
AI-Tool: claude-code
AI-Tool-Version: <버전>
Co-Authored-By: Claude <noreply@anthropic.com>
AI-Model: <모델 ID>
Hooks-Commit: <훅 저장소 짧은 해시>
Signed-off-by: <커미터 이름> <<이메일>>
```

### 제목 · 본문

| 요소 | 규칙 |
| --- | --- |
| `type` | `feat` · `fix` · `docs` · `style` · `refactor` · `perf` · `test` · `build` · `ci` · `chore` · `revert` 중 하나 |
| `subsystem` | 선택. `[a-zA-Z0-9_.-]` |
| 설명 | 50자 이내(유니코드 코드포인트), 명령형 현재형 |
| 본문 | 선택. 제목과 빈 줄로 분리, 한 줄 72자 이내. 무엇보다 왜를 쓴다 |
| 작성 경로 | `git commit -m` 또는 `-F`만. 에디터 경로는 거부한다 |

### 트레일러

| 트레일러 | 값 | 출처 | 신뢰 수준 |
| --- | --- | --- | --- |
| `Task-Id` | 브랜치명의 `<prefix>-<번호>` | 브랜치명. 없으면 커밋 거부 (TRL-002) | 자동 |
| `AI-Tool` · `AI-Tool-Version` | 커밋을 만든 도구 | Claude Code가 하위 프로세스에 주입하는 환경변수 | 강제 — 모델이 만든 값이 아님 |
| `AI-Model` | 모델 ID | Claude Code는 트랜스크립트의 `message.model`, 그 외는 설정값 | Claude Code는 서버 발급 사실, 그 외는 자가 신고 |
| `Co-Authored-By` | 공동 저자 | `AI-Tool`이 `claude-code`일 때만 | 자동 |
| `Hooks-Commit` | 훅 저장소의 짧은 해시 | 훅 클론의 `rev-parse --short HEAD` | 자동, 모든 커밋 |
| `Signed-off-by` | 커미터 | `git log -1 --format='%cn <%ce>'` | 자동, 모든 커밋 |
| `Verify-Bypassed` | 검사를 건너뛴 사실 | 검증 마커의 부재(`--no-verify`) | 자동 |
| `Fixes` | 이 버그를 만든 커밋 해시 | 사람이 씀. 해시 실재를 검증 | 검증됨 |

- 토큰 · 도구 호출 수 트레일러는 없다. 토큰을 커밋에 남길지, 어디에 남길지는 토큰 계량 컴포넌트와 함께 정한다 (`TBD(Q-18)`, 2.03 TRL-004 · TRL-005 폐기). 실행 단위 토큰(`session`)은 커밋이 아니라 실행 기록(§6)과 완료 기록(§1)에 남는다.
- 오케스트레이터가 직접 만드는 커밋(실제치 기록)은 `AI_AGENT` · `CLAUDE_CODE_SESSION_ID` · `CLAUDE_PID`를 지운 환경에서 실행한다. 그래서 `AI-Tool` · `AI-Model` · `Co-Authored-By`가 붙지 않고 지금은 사람 커밋으로 보인다. '프로그램 커밋' 구분은 coding-agent-git-commit-tool GF-130 때 정한다 (3.03 §1 주의점).
- `task/<ID>` 브랜치의 커밋은 제목 · 본문 · 트레일러 어딘가에 그 태스크 ID가 단어로 있어야 한다. 없으면 claude-code-agile-hooks가 커밋을 거부한다 (RAIL-025).

## §3 상태 전이와 판독

| 계약 | 내용 |
| --- | --- |
| 저장 상태 | `To Do` · `In Progress` · `Done` (BL-001) |
| 배정 조건 | `readiness.isReady = true ∧ status = To Do ∧` main에 병합되지 않은 `task/<ID>` 브랜치 없음 (ORC-005). 작업 순서 파일은 읽지 않는다 |
| 착수 판정 | main에 병합되지 않은(`git cherry` 기준) `task/<ID>` 브랜치가 로컬 · 원격 어디든 있으면 착수한 태스크다. 사람이 했든 에이전트가 했든 같다. 브랜치가 병합되거나 지워지면 풀린다 — 병합 뒤 브랜치를 지우는 것이 규칙이고, squash 병합하고 지우지 않은 브랜치는 착수로 남는다(3.03 §1 주의점). backlog.md 화면은 main에서 착수를 보이지 않는다 (2.02 상태와 전이, 3.03 §4 주의점) |
| 승격 | 작성된 구현 계획(SOAP) · AC · DoD가 있는 draft만 `draft promote` (BL-015 · RAIL-020) → 승격 커밋 |
| 작업 순서 | draft든 To Do 태스크든 앞으로 할 일이 새로 생기거나 다시 열리거나 의존이 바뀔 때마다 `--dep`로 의존 정리 → `backlog/work-order.md` 재계산(draft 포함) → 바로 작업 순서 커밋. 의존 출처는 태스크 파일 frontmatter `dependencies`다. 이 파일이 현재 태스크 집합 · 의존과 맞지 않으면 `draft promote`와 착수 검사 두 시점(`task/<ID>` 브랜치 생성 · 전환, `-s "In Progress"`)을 막는다(decision-3). 지금 구현(claude-code-agile-hooks TASK-60)은 `draft promote` · `-s "In Progress"`에서 막고, draft 포함과 생성 직후 강제(TASK-64) · 브랜치 생성 · 전환 시점 검사는 아직 구현 전이다 (BL-016 · RAIL-023) |
| 착수 | 계획 → 리뷰 → 계획 승인: 작성된 구현 계획 · AC · DoD + 사람 서명자의 계획 승인 커밋 `Plan-Approved: <ID>` → `task/<ID>` 브랜치 생성 · 전환(이때 훅이 계획 · AC · DoD, 승인 게이트, 작업 순서 파일을 검사) = 착수 → 그 브랜치에서 `-s "In Progress"`(이때 훅이 같은 착수 검사를 다시 한다) + 시작 기록 커밋(착수 판단이 아니라 기록). 오케스트레이터는 자기 프로세스에서 `git worktree add`로 브랜치를 만들어 훅을 거치지 않으므로, 에이전트 태스크는 세션의 `-s "In Progress"`에서 검사되고 거부되면 오케스트레이터에게 일반 '착수 안 됨' 실패다. main에는 착수 커밋을 만들지 않는다 (BL-017 · RAIL-004 · RAIL-020 · RAIL-023, decision-3) |
| 완료 | `--check-ac` · `--check-dod` 전부 + `--final-summary` + 모든 AC · 규칙 · DoD 표식(`(수동)` AC · DoD 제외) + 커버리지 100%(line + branch) → `-s Done` → 완료 커밋 (BL-009 · RAIL-006 · RAIL-019 · RAIL-022) |
| 단계 커밋 | 단계마다 커밋하고 push하지 않는다. 다음 단계 명령(`draft create` · `draft promote` · `-s "In Progress"` · `-s Done`) 전에 커밋되지 않은 `backlog/` 변경이 있으면 막는다. 커밋 범위는 2.02 전이와 커밋. `task/<ID>` 브랜치의 커밋 메시지에는 그 태스크 ID가 있어야 한다 (RAIL-002 · RAIL-021 · RAIL-025) |
| blocked | 저장 상태가 아니다. 의존으로 막힘은 `readiness.isBlocked`, 재스폰 한도 초과는 오케스트레이터가 사람에게 넘긴다 (ORC-017). 그 표시 방식은 `TBD(Q-3)` |
| 판독 형식 | 기계 판독은 `--json`(`schemaVersion: 1`). `--plain`은 사람과 에이전트의 읽기용 |

## §4 프로세스 · 정책 주입 경계

### 정책 경계

오케스트레이터 코어는 그대로 두고 정해진 확장 지점 하나만 갈아끼운다.

```java
interface AllocationPolicy {
    // 노드 + 현재 상태 → 붙일 에이전트 목록
    List<Allocation> allocate(Node node, NodeState state);
}

record Allocation(Role role, int count, Trigger when, String model, String provider) {}
```

| 항목 | 계약 |
| --- | --- |
| 입력 | 계층 노드(프로젝트 · 마일스톤 · 태스크)와 현재 상태(저장 상태 + readiness + 진행 중인 AC) |
| 출력 | (역할, 개수, 시점, 모델 · 프로바이더) 목록. 빈 목록이면 붙이지 않는다 |
| 선택 | ① `-Dpolicy.class=<구현 클래스>` 시스템 프로퍼티가 있으면 그 클래스 ② 없으면 `ServiceLoader.load(AllocationPolicy.class)`가 찾은 구현 — 정확히 하나면 그것, 둘 이상이면 시작을 거부(모호함), 없으면 시작을 거부(정책 미지정) |
| 실패 | 정책 미지정, 또는 지정한 클래스를 로딩 · 생성하지 못하면(클래스 없음 · `AllocationPolicy` 미구현 · 생성자 실패) 에러 메시지를 내고 실행하지 않는다. 기본 구현으로 대신하는 폴백은 없다 |
| 내장 정책 | 오케스트레이터에 들어 있는 자바 클래스(`DefaultAllocationPolicy`). 명시적으로 고를 때만 쓴다 (예: `-Dpolicy.class=<DefaultAllocationPolicy 정규 이름>`) |
| 기록 | 고른 정책의 클래스(정규 이름)와 선택 경로(`-D` · `ServiceLoader`)를 실행 결과와 실행 기록(§6)에 남긴다 |
| 배포 | ②의 구현은 별도 jar에 `META-INF/services/<AllocationPolicy 정규 이름>` 등록 파일과 함께 넣어 클래스패스에 둔다 |
| 금지 | 정책은 프로세스를 직접 띄우지 않는다. 스폰은 Agent Spawner만 한다 |

위 시그니처의 타입 이름은 자리를 정한 것이고, 필드 구성은 3.03 §1의 Allocation Policy 책임을 따른다.

### 프로세스 경계

| 항목 | 계약 |
| --- | --- |
| 실행 파일 | 기본 `claude`. 역할별로 다른 프로바이더 CLI로 바꿀 수 있다 (ORC-023) |
| 인자 | `-p <프롬프트>` 하나. bare 모드 금지 (ORC-001 · ORC-002) |
| stdin | 닫는다 — 실행 중 세션에 명령을 더 보내지 않는다 |
| 작업 디렉토리 | 태스크 워크트리 `../<repo>-wt/<id>` |
| 프롬프트 | 조상 문서 프리픽스(정적) + 역할별 행동 제약 + 태스크 카드 (`finalPrompt`) |
| 결과 | 종료 코드와 산출물(커밋 · WAL · 카드 변경). 표준 출력은 기록용이다 |
| 종료 | 정상 종료 또는 회수(SIGTERM → 유예 → SIGKILL, 자손 포함) |

## §5 판정 스키마 · WAL

Reviewer · Verifier가 AC마다 남기는 판정 레코드다 (ORC-028). 출력 스키마는 확정이고, 무엇을 pass · fail로 볼지는 `TBD(Q-1)`이다.

```json
{"ac_id": "<AC 식별자>", "verdict": "<판정>", "evidence": "<근거: 파일:라인 · 테스트 로그>", "blocking": true}
```

| 필드 | 뜻 |
| --- | --- |
| `ac_id` | 판정 대상 AC |
| `verdict` | 판정 결과 |
| `evidence` | 판정 근거 |
| `blocking` | 이 판정이 다음 단계 진행을 막는가 |

- 각 역할은 자기 디렉토리에 append-only로 쓴다(WAL). Reviewer는 recap을 함께 남긴다.
- Verifier · DoD는 결정적 검사(테스트 · lint)의 종료 코드를 같은 레코드로 남긴다.
- Logger는 Reviewer · Verifier WAL과 Implementer 커밋 이력을 취합한다. 정성적 기록의 위치는 `TBD(Q-6)`이다.
- `ac_id`의 정확한 표기와 WAL 디렉토리 경로는 `TBD(Q-14)`에서 `runs.jsonl`과 함께 정한다.

## §6 실행 기록 — `runs.jsonl`

`run` 한 번이 끝나면 한 줄의 JSON 레코드를 덧붙인다 (ORC-022). 2.04의 계측(NFR-002 · NFR-006)이 이 파일을 원천으로 쓴다.

| 필드(후보) | 뜻 |
| --- | --- |
| 태스크 ID | 실행한 태스크 |
| 역할 · 모델 | 스폰한 에이전트 |
| 정책 클래스 · 선택 경로 | 고른 정책의 정규 이름과 `-D` · `ServiceLoader` 중 어느 경로로 골랐는지 (§4) |
| 시작 · 종료 시각 | 실행 구간 |
| 종료 코드 · 종료 사유 | 정상 · 타임아웃 · 회수 |
| 커밋 수 | 트레일러 집계 |
| 토큰 합계 | 당분간 `session` — 그 실행의 `claude -p` JSON `usage`(입력(캐시 포함) + 출력)를 `ClaudeCodeRunner`가 읽는다(3.05 ADR-021 예외). 커밋 귀속분 `commits`는 토큰 계량 컴포넌트(이름 미정)가 정해진 뒤(`TBD(Q-18)`) |
| 재시도 · 재작업 횟수 | 자가 치유 배수 · AC 재작업률의 원천 |

필드 이름과 형식은 `TBD(Q-14)`이다. 스케줄 라운드 기록(Ready 집합 크기 · 임계 경로 길이 · 폭 · 실제 동시 가동 수)을 같은 파일에 둘지 따로 둘지도 같이 정한다.

## §7 claude-code-agile-hooks 프로젝트 설정

대상 저장소 루트의 `.claude-code-agile-hooks.json`(옛 이름 `.claude-rails.json`도 읽는다).

```json
{
  "testCommand": "./gradlew test",
  "coverageCommand": "<CI와 같은 커버리지 명령>",
  "coverageReportDir": "reports/coverage",
  "humanSigners": ["human"],
  "testFirst": {
    "sourceGlobs": ["src/main/java/**"],
    "testGlobs": ["src/test/java/**"]
  }
}
```

| 키 | 언제 | 실패 시 |
| --- | --- | --- |
| `testCommand` | 커밋마다 | 커밋 차단 (RAIL-005) |
| `coverageCommand` | push마다 · `backlog task edit <ID> -s Done` 때 | 명령 실패(커버리지 100%(line + branch) 미달) 또는 실행 후 언어별 리포트 위치(아래 표)에 리포트가 없으면 차단. 5개 언어 중 하나가 감지됐는데 키가 없어도 차단. 실행 기록은 `.claude-code-agile-hooks/coverage-log.jsonl`(git 제외) (RAIL-006 · NFR-017) |
| `coverageReportDir` | `coverageCommand`를 돌릴 때 | 언어별 리포트 위치를 바꾼다. 경로 문자열 하나면 감지된 모든 언어에, `{"<언어>": "<경로>"}` 맵이면 적힌 언어만 쓴다. 형식이 틀리면 명령을 돌리지 않고 차단 (RAIL-006 · NFR-017) |
| `humanSigners` | 착수 검사 두 시점 — `task/<ID>` 브랜치 생성 · 전환 때(`git switch -c` · `checkout -b` · `switch` · `checkout` · `worktree add`)와 `backlog task edit <ID> -s "In Progress"` 때(승인 게이트) | 사람 서명자 principal 목록(빈 문자열이 아닌 문자열). 유효한 서명이고 서명자(`%GS`)가 이 목록에 있는 `Plan-Approved: <ID>` 커밋이 없으면 차단. 키가 없거나 비었거나 형식이 틀려도 두 키 설정 방법을 안내하며 차단 (RAIL-020 · ADR-022) |
| `testFirst` | `task/<ID>` 브랜치에서 sourceGlobs에 맞는 파일을 편집할 때 · `backlog task edit <ID> -s Done` 때 | 편집: 체크 안 된 첫 AC의 표식 `<ID>#<n>`과 그 AC의 비즈니스 규칙 표식 `<ID>#B<k>`가 testGlobs 파일에 없으면 차단. Done: 모든 AC · 규칙 표식이 없으면 차단. 텍스트 끝이 `(수동)`인 AC는 편집 · Done 모두 AC 표식을 요구하지 않는다(규칙 표식은 그대로) (RAIL-019 · ADR-020) |

모든 키는 opt-in이다. 키가 없으면 그 검사를 하지 않는다. 단 `coverageCommand`는 아래 매니페스트로 언어가 감지되면 필수이고, `humanSigners`는 backlog.md 프로젝트에서 `task/<ID>` 브랜치를 만들거나 그 브랜치로 전환하거나 `-s "In Progress"`로 옮기려면 필수다. `humanSigners`의 전제는 두 키 구성이다 — 사람 키와 AI 키를 `~/.ssh/allowed_signers`에 서로 다른 principal로 올리고(`gpg.ssh.allowedSignersFile`로 연결), 사람 principal만 이 목록에 적는다. `testFirst`의 glob은 저장소 루트 기준 상대 경로이고 `**`는 디렉토리를 건너 맞는다. 표식 규약은 2.02 태스크 카드 구성을 따른다.

### 언어별 커버리지 리포트 위치

| 언어 | 감지 매니페스트 | 리포트 위치(공식 기본값) | 100% 설정 예 |
| --- | --- | --- | --- |
| Python | `pyproject.toml` · `setup.cfg` · `pytest.ini` | pytest-cov · coverage.py: `htmlcov/` 또는 `coverage.xml` | `--cov-fail-under=100` |
| JavaScript · TypeScript | `package.json` · `tsconfig.json` | Jest `coverageDirectory` 기본값 `coverage/` · Vitest `coverage.reportsDirectory` 기본값 `./coverage` | Jest `coverageThreshold` · Vitest `thresholds.100` |
| Java | `pom.xml` · `build.gradle(.kts)` | JaCoCo Maven `target/site/jacoco/` · Gradle `build/reports/jacoco/test/` | JaCoCo `minimum` 1.0 |
| C++ | `CMakeLists.txt` | 공식 기본값이 없다. gcovr · llvm-cov 출력을 `coverage/`에 둔다 | gcovr `--fail-under-*` |

- 위치는 claude-code-agile-hooks TASK-62 구현의 기본값이고, 공식 문서 근거는 그 저장소 README에 있다. 리포트는 그 실행이 쓴 것만 센다.
- 리포트 위치는 `coverageReportDir`로 바꾼다(위 표).
- `-s Done` 게이트는 기존 push 훅(`pre_push_coverage_check.py`)을 넓히지 않고 새 훅 `require_coverage_on_done.py`가 같은 게이트를 돌린다 (claude-code-agile-hooks TASK-62).

## §8 세션 간 메시지

에이전트 사이 실시간 메시지는 Claude Code의 세션 간 메시징(`ListAgents` · `SendMessage`, 머신 로컬 세션별 소켓)을 쓴다 (ORC-029).

| 항목 | 계약 |
| --- | --- |
| 본문 | 포인터만 — 태스크 ID · AC 번호 · 파일:라인. 본문 내용은 수신자가 파일에서 직접 읽는다 |
| 성격 | 보조 채널. 1차 기록은 WAL이다 |
| 배선 시점 | 에이전트가 할당되는 시점 |
| 전제 | 헤드리스 세션도 inbox 소켓을 바인딩한다(bare 모드 제외). 실환경 확인 `TBD(Q-9)` |
| 폴백 | WAL 디렉토리를 파일 메일박스로 폴링 (ORC-030) |

## §9 대상 프로젝트의 API 예외 처리 규약

대상 프로젝트의 API 예외 처리는 항상 Post/Redirect/Get(PRG) 패턴을 쓴다 (NFR-018, 3.05 ADR-024).

| 단계 | 계약 |
| --- | --- |
| Post | 상태를 바꾸는 요청을 받는다. 처리 중 예외가 나도 그 응답에서 결과 화면 · 본문을 바로 돌려주지 않는다 |
| Redirect | 성공이든 예외든 GET으로 읽을 수 있는 위치로 리다이렉트한다 |
| Get | 클라이언트는 GET으로 결과(예외 정보 포함)를 읽는다. 다시 읽어도 요청이 재전송되지 않는다 |

- 리다이렉트 상태 코드, 예외 정보를 GET 쪽에 넘기는 방식, 리다이렉트 대상 경로 규칙은 미정이다.
- 강제 방법(훅 · 대상 프로젝트 테스트 · 리뷰 중 무엇으로 막을지)은 미정이다.
