# 3.01 시스템 구성

단일 JVM의 agent-orchestrator가 스케줄 · 스폰 · 회수만 하고, 규율(claude-code-agile-hooks) · 포맷(coding-agent-git-commit-tool) · 계측(토큰 계량 컴포넌트, 이름 미정) · 상태(backlog.md) · 판정 규칙(대상 프로젝트의 테스트)은 각자의 자리에 둔다 — 진실의 원천은 Git이다.

## 컴포넌트 지도

| 컴포넌트 | 층 | 책임 | 어디서 도는가 | 장 |
| --- | --- | --- | --- | --- |
| agent-orchestrator | 실행 기반 | 태스크 판독 · 스케줄 · 워크트리 · 스폰 · 회수 · 기록 | 단일 JVM 프로세스 | 3.03 §1 |
| claude-code-agile-hooks | 규율 | 절차 강제 · 품질 · 안전 게이트 · 기록 · 관측 | 각 에이전트의 Claude Code 세션(훅 이벤트) | 3.03 §2 |
| coding-agent-git-commit-tool | 포맷 | 커밋 형식 검사 · 트레일러(태스크 · 도구 · 모델 · 공동 저자 · 훅 버전 · 서명) 부착. 토큰 계량은 하지 않는다 | 대상 저장소의 git 훅(`core.hooksPath`) | 3.03 §3 |
| 토큰 계량 컴포넌트(이름 미정) | 계측 | 역할 세션 · 커밋의 토큰 계량. 저장소 · 측정 방식은 미정 `TBD(Q-18)` | 미정 | 3.05 ADR-021 |
| backlog.md | 상태 | 계층 · 상태 · 의존 · AC · DoD | 대상 저장소의 `backlog/` + CLI | 3.03 §4 |
| 대상 프로젝트 | 판정 규칙 | AC · DoD를 표현하는 테스트 코드(게이트 테스트 포함) | 대상 저장소 | §3 |
| 에이전트 프로세스 | 작업 | 역할별 구현 · 판정 · 관찰 | `claude -p`(또는 다른 프로바이더 CLI), 태스크 워크트리 | 2.01 |

## 의존 방향

- agent-orchestrator → backlog.md CLI: 태스크를 `--json`으로 읽고 상태를 바꾼다. 반대 방향 의존은 없다.
- agent-orchestrator → git: 워크트리 · 브랜치를 만들고, Done 시점에 커밋 트레일러를 읽는다.
- agent-orchestrator → 에이전트 프로세스: 스폰 · 대기 · 회수. 에이전트는 오케스트레이터를 호출하지 않는다.
- agent-orchestrator → `AllocationPolicy`: 역할 · 개수 · 시점 · 모델을 묻는다. 정책은 오케스트레이터 코드를 모른다 (3.04 §4).
- 에이전트 프로세스 → claude-code-agile-hooks: 세션의 도구 호출 · 커밋 · push · 턴 종료가 훅을 거친다.
- 에이전트 프로세스 → coding-agent-git-commit-tool: 커밋이 git 훅을 거친다. 트레일러는 커밋 안에 남는다. 이 훅은 토큰을 재지 않는다.
- 토큰 계량 컴포넌트(이름 미정): 토큰을 어디서 어떻게 재고 어디에 남기는지는 미정이다 `TBD(Q-18)` (3.05 ADR-021).
- claude-code-agile-hooks → backlog.md · 대상 프로젝트 테스트: 태스크 상태 · 브랜치를 확인하고 `testCommand`를 돌린다.
- 컴포넌트 사이의 데이터는 텍스트 산출물(커밋 · 트레일러 · 태스크 카드 · WAL · `runs.jsonl`)로만 오간다 (1.02 P2).

## 시스템 계층

모든 데이터와 변경 이력은 Git과 내장 DB로 이중 영속화된다.

| 번호 | 계층 | 구현 | 책임 |
| --- | --- | --- | --- |
| 1 | 할당자(Pure Allocator) | `WatchService` 또는 DB 이벤트, `ProcessBuilder`, virtual thread(JEP 444) | 태스크 상태를 감시하고 에이전트 프로세스를 할당 · 디스패치만 한다. 프롬프트 조립은 하지 않는다. 단일 클래스가 아니라 3.03 §1의 Board Watcher · Request Queue · Dispatcher · Agent Spawner · Session Registry로 나뉜다 |
| 2 | 내장 DB | SQLite · H2(수직 확장 시 SQLite `:memory:`) | 에이전트의 미세 상태 값 · 작업 큐 · 프롬프트 캐시. 파일 I/O 병목을 피한다 (NFR-012) |
| 3 | 코드 그래프 분석기(CodeGraphAnalyzer) | `JavaParser` | Git 이력이 갱신되면 소스 AST를 정적 분석해 함수 호출 관계 JSON을 뽑는다 |
| 4 | 웹 대시보드 | Javalin + 브라우저 Vis.js | 호출 관계 JSON을 드래그 · 줌 가능한 콜 그래프로 그린다. 태스크 카드 본문의 링크(`http://localhost:8080/dashboard?task=<id>`)로 연다 |
| 5 | 외부 도구 레이어 | Claude Code CLI + `git worktree` | 독립 브랜치에서 1파일 1주제 코딩 |
| 6 | Git 저장소 | `.git` | 진실의 원천 |

## 규칙의 소재지

규칙의 실행과 검증은 대상 프로젝트의 테스트 코드가 맡고, 미들웨어는 그 빌드 결과의 종료 코드(0 또는 1)만 가로채 통과시킬지, 에러 로그를 묶어 재작업을 지시할지만 정한다 (ORC-018, 1.02 P5).

| 자리 | 담는 것 | 예 |
| --- | --- | --- |
| 미들웨어(agent-orchestrator) | 스케줄링 · 프로세스 관리만 | Agent Spawner가 대상 프로젝트의 테스트 명령(예: `gradlew test`)을 돌리게 하고 종료 코드만 심사 |
| 대상 프로젝트 `src/test/.../gate/` | 프로젝트 고유의 규칙 코드 | `ArchitectureGateTest`(ArchUnit 레이어 검증), `ComplianceGateTest`(JavaParser · 리플렉션 기반 `@RestController` 규칙 강제) |
| 대상 프로젝트 `src/main/` | 에이전트가 코딩하는 공간 | — |
| claude-code-agile-hooks 설정 | 커밋 · push 시 돌릴 명령 | `testCommand` · `coverageCommand` (3.04 §7) |

## 디렉토리 구조

### agent-orchestrator

패키지 이름은 3.03 §1의 컴포넌트 이름을 따른다. 기준 패키지 `com.coralstay.orchestrator`.

```text
agent-orchestrator/
├── backlog/                 # 이 저장소 자신의 태스크 카드 (backlog.md)
└── src/main/java/com/coralstay/orchestrator/
    ├── Main.java            # CLI 진입점 — run <taskId> 파싱
    ├── RunCommand.java      # run 흐름 배선 + 실행 결과 기록(runs.jsonl)
    ├── backlog/             # BacklogClient — backlog CLI 래퍼, 태스크 판독 · 스폰 가능 판정
    ├── workspace/           # WorktreeManager — ../<repo>-wt/<id> 워크트리 · task/<id> 브랜치
    ├── spawn/               # AgentSpawner — claude -p 프로세스 기동 · 대기
    ├── registry/            # SessionRegistry — 생존 에이전트 추적 · 회수
    ├── ledger/              # CommitLedger — 태스크 브랜치의 커밋 트레일러 판독
    ├── interceptor/         # [계층 2] 임베디드 DB 연동 캐시 (ContextInterceptor)
    ├── parser/              # [계층 3] JavaParser 정적 분석기 (CodeGraphAnalyzer)
    └── web/                 # [계층 4] Javalin UI 서버 (DashboardServer)
src/main/resources/public/   # [브라우저] index.html · callgraph.html (Vis.js)
.github/workflows/rhel-ci.yml  # AWS RHEL VM 호환성 검증 CI
```

- 계층 2~4의 패키지 이름(`interceptor` · `parser` · `web`)은 자리만 정한 것이고 확정이 아니다.
- 실행 중인 태스크의 워크트리는 저장소 옆 `../<repo>-wt/<id>`에 생긴다.

### 대상 프로젝트

```text
target-project/
├── backlog/                       # 태스크 카드 — 상태 저장소
├── .claude-code-agile-hooks.json  # testCommand · coverageCommand
├── src/main/java/com/target/...   # 에이전트가 코딩하는 공간
└── src/test/java/com/target/gate/ # 프로젝트 고유의 규칙 코드
    ├── ArchitectureGateTest.java
    └── ComplianceGateTest.java
```
