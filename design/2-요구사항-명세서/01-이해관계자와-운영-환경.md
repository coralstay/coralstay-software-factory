# 2.01 이해관계자와 운영 환경

사람은 백로그 승인 · 직접 착수 · 예외 판단 세 지점만 쥐고, 나머지는 단일 JVM 호스트 위에서 역할마다 따로 뜨는 `claude -p` 프로세스가 맡는다.

## 사람

| 주체 | 하는 일 | 제어 수단 |
| --- | --- | --- |
| 개발자(승인자) | 상위 명세를 주고 PM 모드 세션을 깨운다. 태스크 카드를 보드(`backlog browser`)에서 본다 | 기획 지시문 |
| | draft를 검토해 승인 · 반려한다 — 승인 전에는 실행이 시작되지 않는다 | `backlog draft promote` |
| | push 전 코드를 리뷰하고, 운영 저장소로 가는 PR을 직접 연다 | PR |
| | 태스크에 직접 착수한다(`task/<ID>` 브랜치를 만든다). 할당자는 main에 병합되지 않은 `task/<ID>` 브랜치가 있는 태스크에 에이전트를 배정하지 않는다. 브랜치가 병합되거나 지워지면 풀린다 | 착수 = 미병합 task 브랜치 (2.02 상태와 전이) |
| | AC 밖 작업이 발견되면 범위 확장(Phase B 재진입) 여부를 정한다 | 승인 · 반려 (3.02 §2) |
| | Implementer 비정상 종료, Reviewer 왕복 한도 초과, 재스폰 한도 초과로 blocked된 태스크를 판단한다 | 수동 처리 |
| | 동시성 · 자원 상한 파라미터를 조정한다 — 외부 연산 레이어와 내장 DB의 동시 I/O 커넥션 수 | 설정 (2.04) |

## 에이전트 역할

에이전트는 계층 노드(주로 태스크)에 붙는 역할 인스턴스다. 역할마다 별도 프로세스이고 (1.02 P2), 태스크가 끝나면 회수된다 (P3).

| 역할 | 코드 · backlog.md 쓰기 | 트리거 시점 | 산출물 | 비정상 종료 시 | 명세 상태 |
| --- | --- | --- | --- | --- | --- |
| PM 모드 (백로깅 세션) | backlog.md만 — 소스 코드는 건드리지 않는다 | 사람의 기획 입력 | 함수 단위까지 쪼갠 draft · 태스크 카드 | 해당 없음(대화형 단일 세션) | 확정 |
| Implementer | O — 유일한 writer | 태스크 Ready 시 생성 | 커밋, backlog 상태 변경 | 재스폰하지 않는다 — 부분 커밋 상태라 사람이 판단 | 확정 |
| Reviewer | X — 읽기 전용 | AC 커밋마다. 최대 `TBD(Q-11)`회 왕복 후 사람 호출 | 자기 디렉토리 WAL recap + 판정 스키마 `{ac_id, verdict, evidence, blocking}` | `TBD(Q-11)`회까지 재스폰, 초과 시 태스크 blocked | 출력 스키마 확정 · 채점 기준 `TBD(Q-1)` |
| Verifier · DoD | X — 읽기 전용 | AC 커밋마다, Reviewer와 동시 — 서로 기다리지 않는다 | 결정적 검사(테스트 · lint 종료 코드) 결과 | `TBD(Q-11)`회까지 재스폰, 초과 시 태스크 blocked | 확정 |
| Verifier · AC | X — 읽기 전용 | 전체 AC + Reviewer 사이클 종료 후 1회 | AC 판정(같은 스키마) | `TBD(Q-11)`회까지 재스폰, 초과 시 태스크 blocked | 판정 기준 `TBD(Q-1)` |
| Logger | X — 관찰만 | 태스크 시작~종료 전 구간 | Reviewer · Verifier WAL 취합 + Implementer 커밋 이력(세 번째 기록 소스) + 토큰 합계(당분간 실행 단위 `session`, 커밋 귀속분은 토큰 계량 컴포넌트에서) | 해당 없음 — 관찰자라 재스폰 불필요 | 토큰 출처 `TBD(Q-18)` · 정성 기록 위치 `TBD(Q-6)` |
| 마일스톤 노드 에이전트 | X — 읽기 전용 | 자식 태스크가 Done일 때 | 통합 검증 · 기록 | `TBD(Q-7)` | 집계자 역할 확정 · 검증 항목 `TBD(Q-7)` |

- 어느 노드에 몇 개, 어떤 역할을, 언제, 어떤 모델로 붙일지는 Allocation Policy가 정한다 (3.03 §1).
- 4역할 적용 여부는 태스크마다 정한다 (1.02 P8). 단일 에이전트로 충분한 태스크는 Implementer 하나만 붙는다.

## 오케스트레이터 내부 상태

| 변수 | 타입 | 역할 |
| --- | --- | --- |
| `cache` | `ConcurrentHashMap` | 내장 DB와 동기화되는 프롬프트 캐시. 같은 요청에 대한 하위 에이전트의 중복 연산을 막는다 |
| `finalPrompt` | `String` | 태스크 카드 원문에 시스템 규칙과 역할별 행동 제약을 묶은 최종 프롬프트 |
| `taskContent` / `agentId` | 도메인 컨텍스트 | backlog.md가 쪼갠 단위 기능 명세와, 그것을 배정받아 독립 워크트리로 분기될 에이전트의 식별 정보 |

## 실행 환경

| 요소 | 명세 |
| --- | --- |
| 호스트 | 단일 호스트(리눅스, AWS RHEL 서버 기준) 위의 단일 JVM 프로세스. 환경 구축 스크립트(`install-tools.sh`)가 Claude Code · backlog.md CLI · coding-agent-git-commit-tool을 탑재한다 |
| 오케스트레이터 | agent-orchestrator — Java 25, Gradle, 외부 런타임 의존성 없음 |
| 에이전트 | `claude -p` 헤드리스 프로세스. 역할 하나를 다른 프로바이더의 CLI로 바꿀 수 있다 (ORC-023) |
| 작업 공간 | 대상 Git 저장소 + 태스크별 `git worktree`(`../<repo>-wt/<id>`) · `task/<id>` 브랜치 |
| 상태 저장소 | 대상 저장소 안의 `backlog/`(backlog.md 마크다운 카드). 진실의 원천은 Git이다 |
| 규율 · 포맷 | claude-code-agile-hooks(Claude Code 훅) · coding-agent-git-commit-tool(git 훅)이 에이전트 세션과 대상 저장소에 설치된다 |
| 계측 | 토큰 계량 컴포넌트(이름 미정). 어디에 설치되고 어떻게 재는지는 `TBD(Q-18)` (3.05 ADR-021) |
| 언어 런타임 | 대상 프로젝트가 요구하는 런타임(예: Java 25)은 Implementer가 코드를 쓰기 직전까지만 갖추면 된다 |

## 제약

| 제약 | 내용 |
| --- | --- |
| API 분당 한도 | 동시 스폰 수의 자원 상한 중 하나. 값은 실측 전 `TBD(Q-12)` |
| 프로세스 메모리 | `claude` 프로세스 1개의 peak RSS가 자원 상한의 다른 하나. 실측 전 `TBD(Q-12)` |
| 세션 간 전달 | Claude Code에서 세션 간 전달은 순수 텍스트뿐이고, 보내는 쪽의 이력 · 파일은 따라가지 않는다 |
| 헤드리스 세션 | `claude -p`는 프롬프트를 인자 하나로 받고 stdin을 닫은 채 돈다. 세션에 명령을 더 보낼 통로가 없어 대화형 `/clear` 단계가 없다 |
| backlog.md CLI | 외부 오픈소스 의존성. 상태 값은 `To Do` · `In Progress` · `Done` 셋뿐이고, `isReady` 등 readiness는 `--json` 출력에만 있다 (2.02) |
| 판정 | 임의의 명세 충족을 판정하는 일반 절차는 없다. 판정은 프로젝트가 정한 AC · DoD · 테스트의 종료 코드로만 한다 (1.02 P5) |

## 가정

- 대상 프로젝트는 테스트 명령 하나로 통과 · 실패를 종료 코드로 낸다.
- 태스크 하나는 소스 파일 하나에 대응하도록 쪼갤 수 있다 (2.02).
- 에이전트 워크트리 브랜치는 그 에이전트 혼자만 쓴다.
- 대상 저장소의 원격 설정이 main의 force push · 삭제를 막는다.
