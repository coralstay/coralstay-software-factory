# 2.03 기능 요구사항

오케스트레이터는 스케줄 · 스폰 · 회수만 하고, 규율은 claude-code-agile-hooks가, 계측은 coding-agent-git-commit-tool이, 상태는 backlog.md가 맡는다 — 영역별 요구사항은 아래와 같다.

- 규범 용어(MUST · SHOULD · MAY)와 ID 규칙은 0 문서 정보를 따른다.
- 목표 열은 이 요구사항이 이바지하는 1.03의 `G-n`이다.
- 규칙의 실행과 검증은 대상 프로젝트의 테스트 코드가 맡고, 미들웨어는 그 종료 코드만 본다 (3.01 §3). 그래서 ORC 영역에는 "무엇을 통과로 볼지"가 없다.

## BL — backlog.md 사용 규약

| ID | 요구사항 | 목표 | 수용 기준(4.02) |
| --- | --- | --- | --- |
| BL-001 | 태스크의 저장 상태는 반드시 `To Do` · `In Progress` · `Done` 세 값만 쓴다. backlog.md의 저장 상태 어휘를 늘리지 않는다 | G-5 | 4.02 |
| BL-002 | ready · blocked 판단은 `backlog task view <id> --json`(`schemaVersion: 1`)의 `readiness`를 읽어 반드시 한다. `isReady`는 상태 값과 함께 읽는다 | G-5 | 4.02 |

| BL-004 | draft 단계에서 건 의존성은 승격 뒤 실제 태스크 ID로 반드시 다시 설정한다 — `draft promote`는 `DRAFT-n` 의존을 바꾸지 않는다 | G-5 | 4.02 |
